# Adzunova Payment System — Architecture & Product Decisions (Phase 1)

| ID | Decision | Rationale | Status |
|---|---|---|---|
| **D1** | **Stack: MongoDB + Prisma + Cloudflare R2 (no PostgreSQL, no Docker)** | Matches existing `identity-service` and `@adzunova/storage-db` infrastructure on Windows dev environment. Separate `adzunova_payments` database with `pay_` collection prefix isolates ledger from storage and identity. | Accepted |
| **D2** | **Queue, Timers & Rate Limits behind Ports (`QueuePort`, `RateLimitPort`)** | If `REDIS_URL` is configured, use Redis; otherwise use MongoDB atomic `findOneAndUpdate` leases + TTL indexes so local dev and L0/L1 production run without Redis while keeping L2/L3 swap seam intact. | Accepted |
| **D3** | **Money Representation: Integer Paise (`BigInt` / BSON `Int64`) & Basis Points** | Avoids IEEE-754 floating-point drift. Prisma `BigInt` maps to MongoDB `Int64`. JSON DTOs serialize amounts as decimal strings (`"3717000"`) because `JSON.stringify` throws on `BigInt`. | Accepted |
| **D4** | **Single Rounding Module (`@adzunova/money`)** | Round half-up per line item (`Math/BigInt` exact arithmetic). Server-side only; client totals are ignored. | Accepted |
| **D5** | **Double-Entry Immutable Ledger in MongoDB** | Multi-document ACID transactions on MongoDB replica set (`rs0`) ensure `sum(debit) === sum(credit)` per journal entry with unique `idempotencyKey`. Balances are derived or atomically updated inside the same transaction. | Accepted |
| **D6** | **Fee Split & Tax Defaults (Configurable, Versioned)** | Default `cfg_v1`: Brand fee `500 bps` (5%), Creator fee `500 bps` (5%), GST `1800 bps` (18%) on `Deliverable Total + Brand Fee`. Snapshot `feeConfigVersion` and `rateCardItemVersion` on booking creation. Pending CA sign-off for GST/TDS edge cases. | Accepted (Pending CA Sign-off) |
| **D7** | **Escrow / Nodal Copy & Razorpay Route** | RBI rules prohibit holding marketplace funds in a regular operating account. UI must say `"Payment received; work can start"` until Razorpay Route (or RBI-authorized nodal hold) is activated and tested. | Accepted |
| **D8** | **Live-Key Safety Guard** | Application fails closed and refuses `rzp_live_` keys unless `RAZORPAY_MODE=live` AND an audited owner-approval record exists in `pay_config_approvals`. | Accepted |
| **D9** | **Phase 1 Scope Boundary** | Phase 1 covers: request, accept/reject/counter (max 3 rounds), agreement e-sign (in-app OTP + SHA-256 hash), payment (UPI/card/netbanking/virtual account), delivery, review (5-day SLA), link verification, payout (7-day first hold + penny drop), refund, timers, audit log, basic dispute, basic fraud controls. Phase 2/3 (milestones, wallet, instant payout, repeat discount, bonus, subscriptions, credit line) leave schema seams only. | Accepted |
